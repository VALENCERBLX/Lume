Lume

A UI engine for Roblox. Declarative trees, imperative handles, one motion driver, content-driven layout. Everything that made the console feel smooth, with the console taken out.

Derived from the console UI by driftingAurora, dullflowerr, alias and kioukaii (MIT). Their motion, measurement and virtualisation ideas are the core of this library.

Quickstart

--// one app owns the gui, theme, scope, measurement and input
local Lume = require(ReplicatedStorage.lume)
local app = Lume.app({ name = "Inspector" })

--// declarative in, handle out
local window = app:window({ title = "Inspector", width = 320 })
local search = app:field({ parent = window.content, placeholder = "Search", autoWidth = true })
local rows   = app:list({ parent = window.content, mode = "text", maxHeight = 280 })

--// imperative from here: animate, resize, subscribe, dispose
search:on("submitted", function(text)
	rows:append(text)
	window:resize(rows:contentHeight())
end)

window:open()

Module map

core/
state — value, computed, observe, batch. Explicit deps, no global tracking.
scope — ownership; unwinds instances, connections and animations in reverse.
create — descriptor tables to instances, with named refs.
handle — the imperative half every component returns.
motion/
init — one Heartbeat driver; tracks keyed instance + property.
spring — substepped semi-implicit solver, velocity inherited on retarget.
easing · lerp — curves and type-aware interpolation.
layout/
measure — cached text metrics; line height, space gap, exact width.
autosize — content width, viewport clamp, available room.
placement — stack, attach, flip, clamp, center.
virtual — windowing math and stable chunk keys.
input/ · theme/
drag — handle regions, excludes, axis lock, viewport clamping.
focus — one ring per app; click-outside resolved against regions.
keys — named bindings with the typing guard.
theme — colour, type, space, radius, motion tokens; :extend().

Dependencies run strictly downward: components → systems → core. Nothing in core knows a component exists.

Why springs by default

theme.motion.layout — spring, stiffness 190 / damping 24 retargetable
theme.motion.enter — tween, 0.22s outQuint one-shot

Tracks are keyed by instance + property. Retargeting a property replaces only that property's track and hands its velocity to the successor, so a width that changes while it is already moving never restarts from a standstill. Tweens stay for one-shot fades; springs handle anything whose target can change mid-flight — layout, drag release, reveal.

Components

app:window
Draggable content-sized surface. :resize() keeps the top edge anchored while it grows.
app:field
Text input with placeholder crossfade, sanitiser, and measured auto-width.
app:suggest
Autocomplete popover. Prefix-first ranking, spring height, edge flipping.
app:chips
Schema-driven name: value cells that behave as one field. Arrow/Tab traversal.
app:list
Virtualised scroller. text mode chunks lines into few labels; rows mode builds per item.
app:select
Dropdown on the popover layer — never clipped by its parent surface.
app:tabs
Tab strip with a spring indicator that travels across buttons.
app:modal
Scrim + lifted card, Escape to dismiss, input swallowed underneath.
app:tooltip
Hover popover sized from measured text, flipped off viewport edges.
app:button
solid · ghost · outline · accent, with hover and press motion.
app:toggle
Spring knob bound to a Lume.value you can share.
app:slider
Drag anywhere on the track; steps quantise, fill follows a spring.

Handles and scopes

--// every component returns the same shape
handle:instance()
handle:mount(parent)
handle:animate({ Size = ... }, "layout")
handle:on("changed", print)
handle:destroy()

--// plus its own state and methods
handle.value:set(0.5)
window:resize(rows:contentHeight())
--// scopes own everything, in reverse order
local scope = Lume.scope()

scope:add(connection)
scope:add(instance)
scope:add(function() ... end)

--// one call disposes the subtree, its
--// connections and its animations
scope:destroy()
