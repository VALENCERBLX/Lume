01 Lume

Lume — a panel-and-element UI standard for Roblox.

Two primitives. A Panel is every surface: window, command bar, dropdown, tooltip, modal, toast. An Element is everything a surface hosts. Panels size themselves from their elements, grow away from whatever edge they are anchored to, and morph as their content changes.

Every setter returns the receiver, and every setter takes a plain value or a reactive one:

example
local Lume = require(path.to.Lume)

local app = Lume.app({ name = "Inspector" })
local count = Lume.value(0)

local panel = app:panel("window")
    :setTitle("Inspector")
    :setAnchor("bottomRight")
    :setWidth(320)

panel:label(Lume.format(count, "%d selected"))
    :setMuted(true)

panel:field("Search")
    :onSubmitted(print)

panel:button("Refresh")
    :onClicked(function()
        count:update(function(n) return n + 1 end)
    end)

panel:open()

02 App

An app is the one piece of shared state: its host gui, its theme, its root scope, its measurement cache, its focus ring and its key binder.

Layers are full-screen frames ordered by ZIndex, so a dropdown opened from a panel can never be clipped by the panel that spawned it. Ask for one by name and it is created on demand.

03 Chrome

The panel shell: root surface, corner, border, titlebar, content region and shadow.

The root is a CanvasGroup so opening and closing is one GroupTransparency animation instead of a fade per descendant — which is also why children never have to opt into the panel's own fade.

The shadow is a sibling of the root, not a child. A child would be inside the group's render target and clipped by its corner radius, which is the opposite of what a shadow is for.

Creates the shadow, or nothing at all when the theme has no shadow image. Shipping without a baked asset id is deliberate; point theme.shadow.image at your own nine-sliced soft shadow and every panel picks it up.

04 Panel

A panel is every surface Lume draws. Window, command bar, dropdown, tooltip, modal, toast — one implementation, configured by preset.

It does three things nothing else does:

Sizes itself from its children. One pass per frame: ask each child what it wants, sum along the axis, clamp against both the panel's own bounds and the room left on screen, animate to the result. Grows away from what it is stuck to. AnchorPoint does the work; a bottom-anchored panel expands upward and its bottom edge never moves. * Morphs. A pill-shaped bar becomes a rounded rectangle the moment it has enough content to stop being one row tall.

Panels are also elements, so nesting one inside another is how stacking, popovers and inline cards are all the same code path.

05 Presets

Presets are configuration, not subclasses. A window, a command bar, a tooltip and a modal are the same Panel with different numbers, which is why they all get content-driven sizing, anchored growth and the morphing radius without any of them implementing it.

Values are resolved against the theme at apply time, so a preset can say radius = "lg" and mean whatever the current theme calls large.

Looks a preset up by name, falling back to window.

RETURNS Preset

function Module.names(): { string }#

Every preset name, for tooling and docs.

RETURNS { string }

06 Accordion

Sections with headers you click to fold away.

A section's body is a Group, which is the whole trick: everything that works inside a panel works inside a section, because a group already runs the same layout pass a panel does. accordion:section("Advanced") hands you something you can put a toggle, a slider and three labels in.

Collapsing hides the body rather than animating its height. The panel around it is already a spring that morphs when its content changes size, so the fold you see is the panel doing what it does for every other change — one motion system, not a second one fighting the first.

07 Avatar

A player's headshot, round, with initials underneath in case it never arrives.

The initials are not a nicety. A thumbnail that has not loaded is a hole in the layout, and a hole where a face should be reads as an error; two letters read as a person whose picture is still coming.

Thumbnails are requested through rbxthumb://, which resolves without yielding — so an avatar can be built inside a layout pass, which GetUserThumbnailAsync cannot.

12 ColorPicker

A colour picker: a saturation/value square, a hue rail under it, and a hex field beside the swatch.

Hue, saturation and value are the state — not the Color3. Drag the cursor into the black corner of an orange square and the colour becomes black, which in RGB has thrown the orange away: let go, drag back out, and you would come back red. Keeping HSV means the square stays orange the whole time, because the hue was never part of what you changed.

Two events, like the slider: changed fires continuously while dragging and committed fires once on release. Preview on changed, save on committed.

14 Element

The element mixin: what every child of a panel answers to on top of the shared node methods.

The contract is two calls. measure(available) reports the size the element wants given the room on offer and must not mutate anything. commit(inner, vertical, share) then applies the size the panel decided on — which is the earliest moment a fill element can know how wide it is allowed to be.

Splitting them is what lets one pass handle both "size the panel to its content" and "stretch the content across the panel".

fill belongs to commit, never to measure. An element that reported the full available width as its desired width would drag every auto-sized panel straight to its maximum, and a command bar that is always 900px wide is not content-driven, it is just wide. Measure reports what the element naturally wants; commit stretches it afterwards.

15 Field

A text input: optional leading icon, optional prefix, placeholder, and a ghosted completion hint that sits directly after what you have typed.

The hint is positioned by measuring the current text, which is the same trick the console command bar uses — it is what makes inline autocomplete read as part of the input rather than as a separate suggestion.

Masking renders bullets in a mirror label over a transparent input. Roblox has no native masked field, and this is the closest honest approximation; the caret is not visible while masked.

16 Graph

A live series with thresholds: frame times, ping, memory.

The idea is borrowed from Lori (KYRORBLX/Lori), a debug overlay whose graphs auto-scale, carry a unit, and colour themselves against a warning and a failure line. That last part is what makes a debug graph worth looking at: a number is only interesting relative to the number you would accept, so the graph says which samples were unacceptable rather than leaving you to read an axis.

Bars rather than a line, which is what separates it from sparkline. A sparkline is a shape you read at a glance; a graph is samples you read individually, and a bar can be coloured on its own where a line segment belongs to two samples at once.

21 List

A list of rows, virtualised.

Only the rows on screen exist as instances; a pool of them is recycled as you scroll, so ten thousand items cost the same as ten. The list also reports the width of its widest row when it is not filling, which is how a panel ends up exactly as wide as its longest line.

New content follows the view down only when you were already at the bottom. Scroll up to read and the list stops chasing you.

50 Autosize

The layout pass. One function, run once per panel per frame, that turns a panel's children into the size that panel should be.

The rule is: measure, sum, clamp. Children report what they want given the room on offer, the panel adds them up along its axis, and the result is clamped by the panel's own bounds and by how much screen is actually left in the direction it grows. Everything responsive about the library comes out of this: nothing has a hardcoded size, so nothing has to be re-tuned per screen.
